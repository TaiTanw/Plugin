# 操作者须知（v1.7.0）

宿主：Unity 2022.3 Built-in。菜单都在 `Tools`。  
本文只讲「点哪里、文件叫什么、两套设置别混」。实现与约束见 [开发者须知](../dev-wip/README.md)。  
六步流程总图：[操作者须知_六步流程.png](./操作者须知_六步流程.png)。

默认文件夹（可改，见各节）：

```text
Incoming          入库拷贝
IncomingPrefab    ③ Prefab
Art/<名>/         ④ 平铺单元（里面有 Prefab / Model / Texture / …）
AssetBundles/     ⑥ AB（文件名带 _android / _ios，不再分平台子夹）
```

命名一根绳（管线；人工③无 ID2 时用 Incoming 三层夹名）：

```text
ID2
  → ③ Prefab 文件名
  → ④ Art/<同一名字>/
  → ⑥ <同一名字>_android.assetbundle / _ios.assetbundle
```

---

## 1 选区（二者共用，两个按钮不是一回事）

同一窗口：**批量选择器**  
`Tools > 手动操作栏 > 步骤 > [1] 入库`  
管线面板里的「打开批量选择器」也是这一窗。

拖入/浏览外部**模型**（文件夹递归，或单个模型文件）。勾格式只缩小**这一次**列表（关窗不保存）。ID2 可改。OBJ 可勾「轴向 −90°X」（不自动勾），输出到编排会带上。  
`.unitypackage` 不走本窗，见下面「三种把文件交给管线」。

折叠 **「手动端路径」** 只服务人工，管线不读：

| 字段 | 默认 | 谁用 |
|---|---|---|
| 导入根 | Incoming | 仅「执行导入」拷贝到哪 |
| ③ Prefab 根 | IncomingPrefab | 人工③；人工④若选中的是模型会先③ |
| ④ 交付根 | Art | 人工④写出 |
| 交付区预警 | Art/ | 拦住往交付区入库 |

导入期「跳过 Art」钉死 `Assets/Art`，不跟上面的④根走。

两个按钮：

- **执行导入** → 只做人工 [1]：按导入根拷进工程。有 Conflict 会拦住。不填管线表，也不跑后面步骤。
- **输出到编排** → **不拷贝**。把路径 + ID2 + OBJ 轴向勾选交给管线表。Conflict 不挡。真正入库要等管线「运行管线」。轴向只对 `.obj` 有效，在管线④才生效；「执行导入」不读这个勾选。

## 2 导入（二者共用，编辑器全局）

`Tools > 全局导入设置（2）`

Unity 资源一进工程就走这里：总开关、模型/贴图 Importer 分项。  
不看选择器导入根，也不看管线⑤勾没勾。管线/CLI 拷完之后的 Importer 行为仍是这页。  
Art 路径硬跳过（钉死 `Assets/Art`）。

---

## 3 之后分成两框

```text
选区 ──「执行导入」──────────► 人工框（一步一步点）
     └「输出到编排」─┐
浏览单选 / 灰框多选 / CLI ─┴──► 管线框（勾步骤后一次跑）
```

⑥ 产物目录是**一份**导出设置，人工打 AB 和管线⑥都读它，暂不拆。

## 人工框

`Tools > 手动操作栏`，按步骤点。不自动接⑤⑥。

路径改在选择器「手动端路径」，不改管线步骤 SO。

### ③ Prefab

Project 选中已入库的模型 → `步骤 > [③] Prefab`。  
文件名：有任务 ID 用 ID；没有则用 Incoming 里往上三层夹名。  
**不读**管线表上的 ID2。落盘：手动端 Prefab 根。无确认框。

### ④ 平铺

`步骤 > [④]`：普通平铺 / 原子迁移。完整④，**不**接着⑤⑥。

- 选中 **Prefab**：直接平铺。
- 选中 **模型**（`.fbx/.obj/.glb/.gltf`）：**先走③** 写出 Prefab，再平铺。

Art 单元夹名 = 这份 Prefab 的文件名。分类/是否清本次 Art 夹/碰撞体：人工平铺设置。  
人工④默认**不**剥 Missing Script：源上缺脚本则本步失败并在 Console 列出，方便回源补或勾上「剥 Missing Script 再存 Art 副本」。管线④固定剥（只改 Art 副本），所以 pack 丢掉脚本后仍能交外观/网格。  
普通平铺若扫到相对外链 → 问「仍要平铺 / 取消」。取消则本步不做。

### ⑤ 资源处理（批量 ≠ 精准）

参数（阈值、Cutoff、目标 Shader、模型后缀）共用 **TOol** 那份设置。

```text
精准面板（贴图/模型/材质处理）
  勾哪些 Op = 本机记住的勾选
  改眼前这批文件
  「亮度写入 Alpha」只在这里能开；勾上 = 范围内适用文件全部算命中。无条件全池的贴图 Op 都不能进总面板 / 管线⑤
  烤完模型仍像没变：在「贴图处理」精准面板该 Op 下面勾「烤完仍无反应再勾跟材质」（本机记住，默认关）。不在贴图高级设置里。管线④拷材质不看这个勾。

总面板（执行全部 / 分项扫描执行）
  勾哪些 Op = 高级设置里「批量包含」（进工程的 SO）
  路径 = 总面板文件夹列表（本机）
  「纳入贴图/材质/模型」= 本机，只影响本页按钮
  亮度写入 Alpha 在批量里是灰的，勾不上
```

精准勾选不会变成总面板勾选。扫描只在人工⑤，会弹出扫描结果。  
管线⑤**打不开**本总面板；人工入口只有 `手动操作栏 > 步骤 > [⑤]`。

### ⑥ 人工打 AB

选 Prefab 或拣文件夹。文件名 = Prefab 文件名 + `_android` / `_ios`，平铺在导出设置的 AB 根。  
会先确认再打。  
导出设置里「拷到交付夹」只管打好的 AB 要不要再放进 `Deliverables/<Prefab名>/03_assetbundles`。取消它，双端 AB 仍会打到 AB 根。这一步成功后，勾着的 UnityPackage、模型文件、资源信息表照样写进交付夹。双端有一端没打出来，这三项都不写。模型文件和资源表默认关；这两项没写成功，AB 仍然算成功。

管线里关掉步骤 ⑥ 则整次打包不跑，上面几项都不出。

## 管线框

菜单：**`Tools > 自动化管线总面板`**

步骤、三根工作路径、⑤纳哪些大类：步骤 SO（面板「工作路径」）。  
④ 分类/清夹：管线平铺设置。  
⑤ 压图/刷白/烤材质：管线那份资源设置（不是人工总面板那份）。  
⑥ 打到哪、AB 要不要拷进交付夹、要不要 UP、要不要模型文件和资源信息表：和人工共用导出设置。模型文件和资源表默认关。取消「拷到交付夹」仍会先打双端 AB。步骤 ⑥ 关掉则这些勾选都不执行。

默认 ③④⑤⑥ 全开。[2] 不是步骤开关，一直是全局导入那页。

连锁：关③则④⑤关；关④则⑤关。点「运行管线」**一定会入库**。同一物理文件不能在一张表里出现两次。

### 三种把文件交给管线（v1.6.5）

管线 [1] 上面那块灰框是 **预览表**，真正入库要等「运行管线」。三种入口不是同一条路：

| | 点哪里 | 一次几个 | 认什么 | 拷到哪 |
|---|---|---|---|---|
| **单选** | 编排总面板「浏览…」 | **一个**文件 | 模型 **或** `.unitypackage` | 等运行管线 → **管线**导入根 |
| **多选** | 编排总面板灰框 **拖入** | 多个文件，每文件一行/一批 | **只认模型**（`.fbx/.glb/.gltf/.obj`） | 同上 |
| **文件夹批量** | 批量选择器「选择文件夹…」（或往选择器拖文件夹） | 递归勾选格式 | **只认模型** | 「执行导入」→ **人工**导入根；「输出到编排」**不拷贝**，只填管线表 |

- 灰框不要丢文件夹；文件夹只走选择器。
- 选择器「执行导入」有 Conflict 会拦住；「输出到编排」不挡，真正入库仍是管线那一次。
- 同一物理文件不能在一张管线表里出现两次。

### unitypackage：目前只有这一个入口

面板上 **只认** 编排总面板「浏览…」选出的 **一个** `.unitypackage`。表上同时只能有一条 pack（再拖模型或再选别的 pack 会被丢掉，只留第一条 pack）。

CLI `-source` 也可以给一个 `.unitypackage`，走同一套 Runner，不是上面三种面板入口。

**现在不要从这些地方丢 pack：**

- 灰框拖入（不认，进不了表）
- 批量选择器（不收 pack）
- Unity **Project** 窗口把 `.unitypackage` 拖进工程（见下一节）

### [1] 前预处理（不要手动拖包的原因）

「运行管线」对 pack **不会**走 Unity 自带的 Import Package。先在工程外解开，丢掉脚本 / dll / 场景，其余资源和原来的 `.meta` 写进 **管线导入根 / `<ID2>/`**（这一行的 ID2 **只当信封夹名**）。之后在信封里找 **根** Prefab（没被包里别的 Prefab 套着的），每个根再当一批，后面 ③④⑤⑥ 与模型相同。套在里面的子 Prefab 不单独出 Art / AB。信封里一个根 Prefab 都没有 → 入库失败（退出 20），不往下跑。两个根碰巧同名 → 后一份会盖掉 `Art/<这个名字>/`。管线④会剥 Missing Script 再写入 Art（交互脚本不进交付，只保外观）。

往 Project 窗口拖 `.unitypackage` 会走编辑器解包：按**别人工程里的 Assets 原址**写进来，脚本也可能进来，GUID 还可能和现有资源撞车。那 **不是** 管线 [1]，也不会进信封。所以 **不建议** 手动拖入 up。若已经误拖进去了：选中解包后的**根文件夹**再点人工④（按根 Prefab 平铺），**不要**对 `.unitypackage` 文件点④。

步骤组合：

| 勾选 | 实际 |
|---|---|
| ③④⑤⑥ 全开 | 入库 → Prefab → Art → 处理 Art 单元 → 打 Art 里那份 AB |
| 有③无④ | ⑤被带关。⑥若仍开：打 IncomingPrefab 上的包，**文件名仍是 ID2**，只是还没平铺 |
| 无③ | ④⑤被带关。⑥若仍开：没有 Prefab 可打，整趟失败 |
| 关⑤ | 不平资源，仍可④⑥；Art 里是平铺原样 |
| 关⑥ | 停在工程内，不产包 |

开了④，⑥打的是 Art 里那份 Prefab；没开④且源是模型，⑥打 IncomingPrefab。pack ③ 是信封里 Prefab **原样交**，不另写 IncomingPrefab；没开④时⑥打信封里那份（文件名是 Prefab 名，不是信封 ID2）。

### 平铺写完之后

同名可以是两张图。`.fbm` 里的图落到 `image/Texture/<模型名>.fbm/`；分类根上已经有同名文件时，另一张留在 `image/Texture/`。两张都留，字节可以不同。材质槽可以仍指平铺那张，模型导入重绑指套层那张。不要把其中一张当重复删掉。

分类表里没有的后缀进 `Art/<名>/Unknown/`（例如 `.dds`）。Console 会写「包不完整，已继续平铺」。人工整理进对应夹之后，Unknown 可以删。这不单独把退出码打成 41 或 42。

日志里的 `unboundSlots` 是材质空槽，空槽不打 41/42。`textureIdentityWarnings` 大于 0 才是 **42**；模型仍挂着单元外 `.fbm` 才是 **41**。有 41 或 42 时 ⑤⑥ 继续。测试1112（Character01 + Eye_Eyeball）清空旧 Art / Incoming 再跑，整趟是 `exit=0`，两包身份警告和 leftover 都是 0。

⑥ 打 AB 时，部分 FBX 的顶点色会被冲成非白。管线会再刷白并重打 AB。日志里会先看到顶点色诊断 BAD，随后 OK，再一条「重打 Ab 成功」。整趟 `exit=0` 时，交付的是重打那一包。中途网格，或更早导出的 glb，仍可能发黄。

信封夹名（这一行的 ID2，例如路径折出来的 `Users_16028_Desktop`）只是导入根下的文件夹。Art 与 AB 的名字是根 Prefab 名。

### 弹窗（面板 / CLI 在这里分岔）

- **点「运行管线」+ Quiet 勾上（默认）**：过程不弹窗；结束也不弹完成框。
- **点「运行管线」+ Quiet 勾掉**：整趟结束后弹完成/失败框；⑥ 也可能先问是否导出。
- **CLI**：强制不弹窗（不管步骤 SO 上 Quiet 勾没勾）。不是退出编辑器的意思。

### 本趟结束后清空（步骤 SO，跟 Quiet 同页）

默认关。勾上后，**整趟跑完**才清勾选根下的全部文件（根夹留下）。入库/Prefab/④/⑥ 中途硬失败不清，方便排错。不弹确认框，和 Quiet 不是一回事。CLI 跟步骤 SO 勾选，不会像 Quiet 那样强制改。先清 Art，挂起导入、删完再刷新，避免残留 glTF 按已删贴图重导刷屏。

- **清空导入区**：Incoming 和 IncomingPrefab **一起**清。
- **清空交付根**：Art 整棵清。⑥ 打出的 AB / 交付夹不在这些根里，不会被这勾选删掉。

### CLI（同一套 Runner）

先关掉占用本工程的 Editor。`-source` 一个文件（不能是文件夹批量）。可选 `-materialId` 覆盖 ID2。步骤开哪些跟步骤 SO。

```text
"<Unity2022.3>\Unity.exe"
  -batchmode -nographics -quit
  -projectPath "D:\UnityMyCSProject\UnityProject\Plugin2022"
  -executeMethod PipelineCli.Run
  -logFile "<路径>"
  -source "<工程外模型 / .unitypackage 或 Assets/…>"
  [-materialId <名>]
```

| 退出码 | 含义 | 本趟后面 |
|---:|---|---|
| 0 | 成功 | — |
| 10 / 20 / 30 / **40** | 参数 / 导入 / Prefab / ④硬失败（含 glTF 缺伴生） | **停** |
| **41** / **42** | leftover 外部 `.fbm` / 贴图身份 | ⑤⑥继续 |
| 50 | ⑤硬失败 | ⑥继续 |
| 60 | ⑥全失败 | 停 |
| 80 | 未捕获异常 | — |
| 70 | 预留 | — |

看日志 `[Pipeline] exit=N`。

## 别混的三件事

1. **选区两个按钮**：拷进工程 ≠ 交给管线。  
2. **两套根**：手动端路径（选择器）≠ 管线工作路径（步骤 SO）。默认文件夹相同，改一边另一边不会跟。  
3. **两套⑤**：人工总面板 / 精准 = TOol 设置 + 本机勾选；管线⑤ = 编排设置。管线面板不会打开人工总面板。  
4. **三处「拖」**：灰框只拖模型（多选）；pack 只用编排「浏览…」（单选）；不要把 `.unitypackage` 拖进 Project。文件夹批量走选择器，选择器不收 pack。
